# 索引和视图

## 文章导读
本篇是数据库课程中**索引与视图**章节的作业记录。原稿保留了「按要求完成数据库与表格、按要求处理表格」的题面结构，本文据此系统讲解索引与视图的创建、使用及区别，帮助巩固这一阶段的数据库知识。

> 说明：原标题「试图」为「视图」的笔误，本文按「视图」讲解。

## 一、作业说明
作业分两部分：一是按照要求完成数据库和表格的创建；二是按要求处理表格，涉及索引与视图的相关操作。

## 二、索引（Index）
索引用于**加快查询速度**，是数据库性能优化的核心手段之一。

**1. 创建索引**
```sql
CREATE INDEX idx_gid ON goods(gid);
```

**2. 查看索引**
```sql
SHOW INDEX FROM goods;
```

**3. 删除索引**
```sql
DROP INDEX idx_gid ON goods;
```

**索引的优缺点：**
- 优点：大幅加快 `WHERE`、`JOIN`、`ORDER BY` 的查询速度
- 缺点：占用额外存储空间，且会降低 `INSERT/UPDATE/DELETE` 的速度，应针对高频查询字段创建，不宜滥用

## 三、视图（View）
视图是基于查询语句生成的**虚拟表**，可以简化复杂查询、屏蔽敏感字段。

**1. 创建视图**
```sql
CREATE VIEW v_goods AS
SELECT gid, name, price FROM goods;
```

**2. 查询视图**
```sql
SELECT * FROM v_goods;
```

**3. 删除视图**
```sql
DROP VIEW v_goods;
```

## 四、索引与视图的区别
| 对比项 | 索引 | 视图 |
|---|---|---|
| 本质 | 物理存储结构，加快查询 | 虚拟表，封装查询语句 |
| 作用 | 提升查询性能 | 简化查询、权限隔离 |
| 是否占用存储 | 占用（存储索引数据） | 不单独存储（存储的是定义） |
| 对数据的影响 | 影响写操作性能 | 一般不影响底层数据 |

## 五、小结
索引优化查询、视图封装查询，二者各有侧重。做题时应先理解题目要求的是「建索引加速」还是「建视图简化」，再选择合适的语句完成，避免混淆。
